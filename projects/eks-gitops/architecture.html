EKS GitOps Architecture

How application code becomes a continuously reconciled Kubernetes deployment.

Back to portfolio

System Objective

CI builds the release; GitOps deploys and continuously verifies it.

The application source and the desired Kubernetes state are intentionally separated. CircleCI packages each code change into a container image, while Argo CD watches the manifest repository and makes the EKS cluster match that declared state.

Developer push→CircleCI→Container registry→Manifest update→Argo CD→Amazon EKS

Request / Data Flow

How a change reaches users

  1. A developer pushes an application change to the source repository.
  2. CircleCI tests the application and creates a multi-stage Docker image.
  3. The versioned image is published to the container registry.
  4. The pipeline updates the Kubernetes manifest repository with the new image version.
  5. Argo CD detects the desired-state change and synchronizes it to Amazon EKS.
  6. The Kubernetes Service and load balancer route user traffic to healthy application pods.

Engineering Decisions

Separate CI from deployment

CI produces immutable versioned images, while Argo CD deploys only the state approved in Git. This keeps releases auditable and avoids giving the build pipeline direct cluster control.

Reliability & Failure Handling

Reconcile drift and replace unhealthy workloads

  1. Terraform creates repeatable AWS networking and EKS infrastructure from code.
  2. EKS worker nodes run across separate Availability Zones to reduce single-zone risk.
  3. Argo CD detects configuration drift and reconciles the cluster back to the declared state.
  4. Kubernetes replaces unhealthy pods and supports controlled rollout behavior.

Tradeoffs

More repositories, clearer control

Separating application source from deployment manifests adds coordination overhead, but improves auditability, rollback, and access boundaries.

Future Improvements

Measure and automate release safety

Add progressive delivery, automated rollback metrics, policy enforcement, secret management, and cluster observability.
